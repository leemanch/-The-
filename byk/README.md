# Оценки The БЫК

Мобильный сайт для компании друзей. У каждого участника свой список блюд текущего визита. После публикации вкус, внешний вид, комментарий, дата и имя автора доступны по ссылке `/#public` без регистрации.

## Запуск на сервере

Нужен Docker Engine с Docker Compose v2 и поддержкой Linux-контейнеров. Распакуйте ZIP и перейдите в каталог `byk`, в котором лежит `compose.yaml`. Выполняйте дальнейшие команды из этой папки.

**Сборка из исходников** (первый запуск требует интернета):

```sh
docker compose up -d --build
```

**Запуск готового образа** для сервера с процессором x86-64 (AMD64/Intel). Положите переданный файл `the-byk-linux-amd64.tar` рядом с папкой `byk` и выполните:

```sh
docker load -i ../the-byk-linux-amd64.tar
docker compose up -d --no-build
```

Откройте [локальную главную](http://127.0.0.1:28741). Для проверки сервера выполните `curl -fsS http://127.0.0.1:28741/health` — ответом будет `ok`. Для другого порта укажите, например, `PORT=28742` в файле `.env` рядом с Compose и повторите запуск. Журнал доступен через `docker compose logs --tail=50 app`.

## Как оценивать блюда

1. Зарегистрируйтесь по фамилии, имени и паролю от 3 до 30 символов. Для входа используется та же пара фамилия + имя, регистр букв игнорируется. Совпадающие пары должны выбрать различимые варианты имени.
2. На главной нажмите **Добавить блюдо**. Начните печатать и выберите подсказку. Если названия нет, выберите **Другое** и введите от 1 до 50 символов. Добавьте остальные блюда визита. Ошибочную позицию можно убрать.
3. Нажмите **Оценить блюдо**. Для каждого блюда отдельно выберите вкус и внешний вид от 1 до 10, при желании оставьте комментарий до 1000 символов. **Продолжить** публикует одну оценку и открывает следующее блюдо. Остаток списка хранится в аккаунте и доступен после перезагрузки или входа с другого телефона.
4. Круглая кнопка с инициалами имени и фамилии открывает профиль. Там видны дата регистрации и оценки, сгруппированные по московской дате публикации. В профиле автор может изменить баллы и комментарий или удалить оценку с подтверждением. При изменении дата визита сохраняется. Ссылки на публичную ленту есть в профиле и на экранах входа и регистрации. Удаление аккаунта с подтверждением пароля стирает оценки, очередь и сессии из рабочей базы.

## Заполнение каталога

При первом запуске этой версии в SQLite добавляются 288 уникальных названий из [меню ресторана на улице Кирова в Калуге](https://klgkirov.thebull.ru/takeout/) за 24.11.2026, включая напитки. Повторный запуск сохраняет изменения владельца. Для ручного обновления впишите названия в `catalog.txt` в UTF-8, по одному названию на строку. Пустые строки и строки с начальным знаком `#` пропускаются. Допустимо до 200 символов в названии из каталога. Для варианта «Другое» предел составляет 50 символов. Сохраните файл и выполните:

```sh
docker compose run --rm --no-deps app import /config/catalog.txt
```

Команда атомарно заменяет весь каталог содержимым файла. При ошибке верните исправленный файл и повторите команду. Повторяющиеся названия с разным регистром объединяются. Уже добавленные блюда и опубликованные оценки сохраняют прежние названия. Новые подсказки доступны сразу. Пользовательские названия из «Другое» сохраняются в визите и оценках.

## Доступ с телефонов по HTTPS

Для `ratingthebyk.ru` попросите владельца сервера прислать **публичный IPv4, на котором его сервер принимает входящие соединения**. У VPS он обычно указан в панели хостинга в разделе «Сеть» или «IP-адреса». В DNS создайте или измените запись типа `A` для имени `@` и вставьте полученный IPv4 без порта. TTL оставьте по умолчанию.

### nginx на хосте Linux

В комплекте есть файл `nginx/ratingthebyk.ru.conf`. Он рассчитан на nginx, который работает непосредственно на сервере и принимает HTTP на порту 80. Проверьте приложение и подключаемые каталоги конфигурации:

```sh
curl -fsS http://127.0.0.1:28741/health
sudo nginx -T 2>&1 | grep -E 'include.*(conf.d|sites-enabled)'
```

Если активен `/etc/nginx/conf.d/*.conf`, из папки `byk` выполните:

```sh
sudo cp -i nginx/ratingthebyk.ru.conf /etc/nginx/conf.d/
sudo nginx -t && sudo systemctl reload nginx
```

Если используется только `/etc/nginx/sites-enabled/*`, скопируйте файл в этот каталог. Если сайт уже настроен, отредактируйте его существующий блок. При изменении порта в Compose согласуйте с ним `proxy_pass`.

После обновления DNS проверьте с другого устройства, что `http://ratingthebyk.ru/health` возвращает `ok`. Для HTTPS должны быть открыты входящие порты 80 и 443. Если Certbot ещё не установлен, выберите ОС сервера в [инструкции по установке Certbot с модулем nginx](https://certbot.eff.org/instructions?ws=nginx&os=snap). Затем выполните на сервере:

```sh
sudo certbot --nginx -d ratingthebyk.ru --redirect
curl -fsS https://ratingthebyk.ru/health
sudo certbot renew --dry-run
```

Укажите `COOKIE_SECURE=true` в файле `.env` проекта и примените настройку командой `docker compose up -d --no-build`. Если nginx работает внутри отдельного контейнера, подключите оба сервиса к общей Docker-сети и укажите адрес приложения по его сетевому имени и внутреннему порту 8080. Сертификат подключите тем же способом, что и для остальных сайтов этого прокси.

### Caddy на хосте Linux

По умолчанию порт доступен только на самом сервере. Для доступа друзей привяжите свой домен к публичному IP сервера через DNS, откройте входящие TCP-порты 80 и 443 для веб-сервера. При наличии записи AAAA адрес IPv6 также должен вести на сервер.

Если на хосте используется **Caddy**, добавьте блок в его Caddyfile, заменив домен своим. При изменении `PORT` укажите тот же порт здесь.

```caddyfile
byk.example.com {
    reverse_proxy 127.0.0.1:28741
}
```

Проверьте конфигурацию и перечитайте её (пример для Linux с установленным сервисом Caddy):

```sh
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Включите защищённые cookie, добавив `COOKIE_SECURE=true` в файл `.env` в папке проекта, затем выполните `docker compose up -d --no-build`. Откройте свой HTTPS-адрес и зарегистрируйтесь. Прямая ссылка для гостей имеет вид `https://ваш-домен/#public`. Настройка предполагает Caddy на хосте. При установленном nginx можно направить существующий HTTPS-виртуальный хост на тот же локальный порт. [Документация Caddy](https://caddyserver.com/docs/quick-starts/reverse-proxy)

## Данные и резервное копирование

SQLite, сессии и очередь хранятся в именованном томе `data` в каталоге `/data`. Используйте постоянное имя папки проекта или одно и то же имя проекта Compose. Обычные обновления через `docker compose up -d --build` сохраняют том. Флаг `down -v` уничтожает данные.

Следующие команды предназначены для Linux shell. Краткая остановка записи позволяет скопировать базу вместе с журналом WAL. Не запускайте импорт во время копирования. Для работы с архивом используется временный контейнер Alpine. Копия содержит пользовательские данные и хеши паролей. Храните её в закрытом месте вне сервера, отдельно сохраните `catalog.txt` и `.env`.

```sh
mkdir -p backups
chmod 700 backups
backup="byk-$(date +%Y%m%d-%H%M%S).tar.gz"
cid=$(docker compose ps -q app)
docker pull alpine:3.23
docker compose stop app
docker run --rm --volumes-from "$cid:ro" -v "$PWD/backups:/backup" alpine:3.23 tar -czf "/backup/$backup" -C /data .
docker compose start app
docker run --rm -v "$PWD/backups:/backup:ro" alpine:3.23 tar -tzf "/backup/$backup"
```

**Восстановление в отдельный том**. Укажите имя существующего архива. Пример поднимает копию на порту 28742 с отдельным именем проекта. Выберите свободный порт и новое имя проекта. Восстановление прервётся, если в целевом томе уже есть файлы.

```sh
backup=byk-YYYYMMDD-HHMMSS.tar.gz
export COMPOSE_PROJECT_NAME=byk-restore PORT=28742
docker compose create --no-build app
cid=$(docker compose ps -aq app)
docker run --rm --volumes-from "$cid" -v "$PWD/backups:/backup:ro" alpine:3.23 sh -ec 'test -z "$(ls -A /data)"; tar -xzf "/backup/$1" -C /data' sh "$backup"
docker compose start app
curl -fsS http://127.0.0.1:28742/health
```

Откройте публичную ленту копии и проверьте оценки. При переносе на другой сервер сначала загрузите или соберите образ. Для переключения на восстановленную копию измените порт в HTTPS-прокси. Переменные `COMPOSE_PROJECT_NAME` и `PORT` в примере действуют в текущей оболочке.

## Устройство и ресурсы

Go, SQLite с драйвером на чистом Go, статические HTML/CSS/JS внутри исполняемого файла. Работает один непривилегированный контейнер. Используется WAL, запросы к базе проходят через одно соединение. Пароли защищены PBKDF2-HMAC-SHA256 с индивидуальной случайной солью и 600 000 итераций. Сессии действуют 30 дней. Браузер получает случайный токен в HttpOnly-cookie с SameSite=Lax, в SQLite хранится SHA-256 токена. Compose задаёт лимит памяти 128 МиБ, ориентир для сборщика мусора Go 80 МиБ и ограничение журналов Docker.

При локальной проверке Linux/amd64 размер образа по Docker составил **15 087 071 байт (14,39 МиБ)**. В предыдущей версии после теста с 12 пользователями Docker Stats показал **2,88 МиБ** в спокойном состоянии. Это одно измерение, пиковое потребление под нагрузкой может быть выше. Тест охватывал параллельные регистрации, добавление блюд, сохранение оценок и чтение ленты. Проверены сохранность сессий и оценок после перезапуска, а также пользовательский сценарий в браузере шириной 375 пикселей.

Цель до 200 МБ относится к небольшому экземпляру приложения. Размер базы, WAL и резервных копий растёт. Docker Engine, виртуальная машина Docker Desktop, сборочный кеш и HTTPS-прокси требуют отдельных ресурсов. Для сервера с малым диском используйте готовый образ.

```sh
docker stats --no-stream "$(docker compose ps -q app)"
docker image inspect the-byk:local --format '{{.Size}}'
docker run --rm --volumes-from "$(docker compose ps -q app):ro" alpine:3.23 du -sh /data
```

## Исходники

- `main.go` — HTTP, схема SQLite, очередь, публикация, лента и импорт.
- `auth.go` — регистрация, пароль, сессии и удаление аккаунта.
- `web/` — интерфейс на русском языке, без внешних шрифтов и библиотек.
- `Dockerfile`, `compose.yaml`, `go.mod`, `go.sum` — сборка и зависимости.

Без Docker установите Go 1.25 или новее и выполните `go run .` из папки проекта. В этом режиме база создаётся в `data/byk.db`. Путь задаётся через `DB_PATH`, адрес прослушивания — через `LISTEN`. Импорт выполняется командой `go run . import catalog.txt`.
